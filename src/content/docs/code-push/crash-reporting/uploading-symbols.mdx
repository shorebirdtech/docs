Shorebird uses a fork of Flutter to build your app. This means Shorebird has
built its own copy of Flutter's engine, which means that the symbols included in
the Flutter.framework or libflutter.so are slightly different from the upstream
Flutter engine.

To see C++ symbols from Shorebird's fork of Flutter's engine in your crash
reports, upload the symbols to your crash reporting tool.

:::caution[Engine symbols and Dart symbols are separate uploads]

There are two kinds of symbols:

- **Shorebird engine symbols** cover native engine frames, such as
  `libflutter.so` on Android and `Flutter.framework` on iOS. On iOS, get them
  from the console or the [download URL](#symbols-for-ios). On Android, use the
  [download URLs](#symbols-for-android).
- **Dart symbols** cover Dart frames. You only need them if you build with
  `--obfuscate` or `--split-debug-info`. See
  [Dart symbols for obfuscated builds](#dart-symbols-for-obfuscated-builds).

A mistake to avoid is uploading only the `--split-debug-info` output with
`firebase crashlytics:symbols:upload`. Those files don't contain Shorebird's
engine symbols, so native engine crashes stay unsymbolicated. To make both Dart
and native crashes readable, upload both kinds of symbols. See
[Uploading engine symbols to Crashlytics](#uploading-engine-symbols-to-crashlytics).

Upload Dart symbols as part of each build. Some tools only symbolicate crashes
reported after the upload. For example, Crashlytics needs Dart symbols uploaded
before an obfuscated build reports a crash.

:::

Google provides instructions for how to integrate various crash reporting tools
into your Flutter app:

https://docs.flutter.dev/cookbook/maintenance/error-reporting

# Getting symbols from the console

For iOS and macOS releases, the "Artifacts" tab of the release page in
Shorebird's console links to the Flutter engine's dSYM, next to your release's
build artifacts. The console doesn't link to Android engine symbols. Use the
[download URLs](#symbols-for-android) instead.

The current URL format for this tab is:

```
https://console.shorebird.dev/orgs/<org-id>/apps/<app-id>/releases/<release-id>/artifacts
```

# Manual instructions (only needed for CI or scripts)

If you need a way to download symbols as part of a CI pipeline it's possible
with the following information:

For a given Flutter version you will need the Flutter engine hash to download
the symbols. This hash is displayed in `shorebird doctor` output:

```
$ shorebird doctor
Shorebird 1.6.49 • git@github.com:shorebirdtech/shorebird.git
Flutter 3.32.5 • revision 44a8ada33bdbe7f25a49e7dcf13c5c1f648129fd
Engine • revision f275acddf709f94ef38af54adb2c1a0a0a90b5c6
```

In this case, `f275acddf709f94ef38af54adb2c1a0a0a90b5c6` is the engine hash.

## Symbols for iOS

Assuming engine hash `f275acddf709f94ef38af54adb2c1a0a0a90b5c6`, the iOS symbols
can be downloaded from the following URL:

https://storage.googleapis.com/download.shorebird.dev/flutter_infra_release/flutter/f275acddf709f94ef38af54adb2c1a0a0a90b5c6/ios-release/Flutter.framework.dSYM.zip

For some older Flutter versions, the file is named `Flutter.dSYM.zip` instead of
`Flutter.framework.dSYM.zip`.

## Symbols for Android

Assuming engine hash `f275acddf709f94ef38af54adb2c1a0a0a90b5c6`, the Android
symbols can be downloaded from the following URLs:

https://download.shorebird.dev/flutter_infra_release/flutter/f275acddf709f94ef38af54adb2c1a0a0a90b5c6/android-arm64-release/symbols.zip
https://download.shorebird.dev/flutter_infra_release/flutter/f275acddf709f94ef38af54adb2c1a0a0a90b5c6/android-arm-release/symbols.zip
https://download.shorebird.dev/flutter_infra_release/flutter/f275acddf709f94ef38af54adb2c1a0a0a90b5c6/android-x64-release/symbols.zip

# Uploading engine symbols to Crashlytics

On Android, Crashlytics only reports native crashes if you set up
[NDK crash reporting](https://firebase.google.com/docs/crashlytics/android/get-started-ndk),
which the FlutterFire plugin doesn't add for you. Unzip each architecture's
`symbols.zip` into its own subdirectory of one folder, because every zip
contains a file named `libflutter.so`. Then pass that folder to the Firebase
CLI, which searches it recursively for `.so` files:

```sh
firebase crashlytics:symbols:upload --app=FIREBASE_APP_ID PATH/TO/SYMBOLS
```

On iOS, upload the engine's dSYM zip in the dSYMs tab of the Crashlytics
dashboard, or pass it to Crashlytics' `upload-symbols` script, which accepts zip
archives of dSYMs. See
[Get readable crash reports](https://firebase.google.com/docs/crashlytics/ios/get-deobfuscated-reports)
for how to run the script, or run it with `--help` for its options.

# Dart symbols for obfuscated builds

The engine symbols above cover Flutter's C++ code. If you build with
`--obfuscate` or `--split-debug-info`, your Dart code's debug information is
also removed from the app, and your crash reporting tool needs it to show
readable Dart stack traces.

`--split-debug-info` writes that debug information to a directory, one file per
architecture, such as `app.android-arm64.symbols` or `app.ios-arm64.symbols`:

```sh
shorebird release android --obfuscate --split-debug-info=build/symbols
```

If you pass `--obfuscate` without `--split-debug-info`, Shorebird writes the
files to `build/shorebird/symbols`.

Upload the files in that directory by following your tool's guide:

- [Sentry: Debug Symbols](https://docs.sentry.io/platforms/dart/guides/flutter/debug-symbols/)
- [Crashlytics: Get readable crash reports](https://firebase.google.com/docs/crashlytics/flutter/get-deobfuscated-reports)

:::caution[iOS]

On iOS, the symbol files are only usable by crash reporting tools for releases
built with Flutter 3.47.5 or newer, the default Flutter version since Shorebird
1.6.123. What counts is the Flutter version the release was built with, so a
release that pins an older version with `--flutter-version` still gets the old
files. With those, tools such as `sentry-cli` report finding no debug
information files, even though the upload command succeeds. Release again with
Flutter 3.47.5 or newer to get readable Dart stack traces on iOS.

:::

`shorebird patch` accepts the same flags, and an obfuscated release's patches
are obfuscated too. When a patch writes to the same directory as an earlier
build, whether the default or a path you pass again, it replaces that build's
files, because the file names are the same. Upload or copy the files after every
build, before you run the next one.
