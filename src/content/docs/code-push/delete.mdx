:::note[Deleting is permanent]

Once an app, release, or patch is deleted, it can't be restored, including by
Shorebird support. If you're only trying to stop a patch or hand off an app, see
[Before you delete](#before-you-delete) for options that can be undone.

:::

The Shorebird console shows a confirmation dialog before any of these deletions,
so you can review what's about to be removed before anything happens.

## What each deletion removes

| You delete | What is removed                                                                                                                                            |
| ---------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------- |
| A patch    | Patches can't be deleted on their own. They are removed with their release.                                                                                |
| A release  | Deleting all platforms removes the release and every patch published to it. Deleting one platform removes only that platform's release and patch binaries. |
| An app     | The app and every release, patch, and artifact belonging to it.                                                                                            |
| An account | Your personal organization and all of its apps, releases, patches, and artifacts.                                                                          |

## Delete a patch

Individual patches can't be deleted. A patch is removed along with the release
it belongs to, or the app that owns that release.

If you want to stop serving a patch, you can roll it back. A rollback remotely
uninstalls the patch from end users' devices and falls back to the previous
patch or the base release. You can undo a rollback later if you need to.

## Delete a release

The delete dialog asks which platforms to delete, and the answer changes what
happens:

- **All** deletes the release itself, along with its artifacts and every patch
  published to it. Devices will no longer receive patches for that release
  version.
- **A single platform** deletes that platform's release and patch binaries. The
  release itself remains, and the other platforms are untouched.

In both cases, the deleted binaries can't be restored.

See [Delete releases](/code-push/release#delete-releases) for the steps and for
the platform selection dialog.

## Delete an app

1. Navigate to the app in the
   [Shorebird console](https://console.shorebird.dev/).
2. Go to the **Settings** tab.
3. In the **Danger Zone**, select **Delete**.
4. Confirm in the dialog that appears.

Deleting an app also deletes every release, patch, and artifact associated with
it. Copies of the app that are already installed on end users' devices keep
working normally, but they won't receive new patches.

If you want to hand an app to someone else, use **Transfer Ownership** in the
same Danger Zone instead.

## Delete an account

Deleting your account removes your personal organization and everything in it.
If you own any team organizations, transfer or delete those first.

## Before you delete

Depending on what you're trying to do, one of these might be a better fit:

- **A bad patch is live.** [Roll it back](/code-push/rollback). You can undo the
  rollback later.
- **You want to test a patch first.** Publish to a
  [staging track](/code-push/guides/staging-patches).
- **You are handing off an app.** Transfer ownership of the app or the
  [organization](/account/orgs).

If you're not sure which option is right,
[reach out](mailto:contact@shorebird.dev) and the Shorebird team can help you
decide.
